# CUDA inference for an EXISTING environment (the QGIS plugin venv, a conda
# env, a bare virtualenv). See docs/GPU.md for the full procedure.
#
# THIS FILE IS A SWAP, NOT AN ADDITION.
# 'onnxruntime' and 'onnxruntime-gpu' both provide the `onnxruntime` module and
# MUST NOT be co-installed — pip will not stop you, and the result is a broken
# import or a silent CPU session. Uninstall the CPU wheel FIRST:
#
#     <venv>/bin/pip uninstall -y onnxruntime
#     <venv>/bin/pip install -r requirements/onnxruntime-gpu.txt
#
# Then verify CUDA is actually offered — installing is not the same as working:
#
#     <venv>/bin/python -c \
#       "import onnxruntime as ort; print(ort.get_available_providers())"
#
# 'CUDAExecutionProvider' must appear in that list. If it does not, the wheel
# and your driver/CUDA runtime do not match; see docs/GPU.md.
#
# Deliberately NOT reachable via -r from base.txt / plugin.txt / ci.txt: those
# install the CPU wheel, and pulling this in alongside would break them.
# Container builds use requirements/gpu.txt instead (whole environment).
#
# VERSION PINNING IS HARDWARE-DEPENDENT. The [cuda,cudnn] extras ship the CUDA
# userspace as wheels, so no system CUDA install is needed — but onnxruntime-gpu
# 1.27 moved those extras to CUDA 13 (nvidia-*-cu13) while earlier releases use
# cu12. If the target machine's driver is too old for CUDA 13, pin a cu12-era
# release here instead, e.g.:
#
#     onnxruntime-gpu[cuda,cudnn]==1.22.0
#
onnxruntime-gpu[cuda,cudnn]
